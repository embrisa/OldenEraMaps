# RMG Task: Branch Mirroring And Naming

## Goal

Make generated player branches easier to audit and harder to accidentally desynchronize.

## Desired Behavior

For symmetric generated maps:

- Mirror every player branch with the same zone count.
- Mirror branch connection count and ordering.
- Mirror road style and route shape.
- Mirror reward structure.
- Mirror guard values and weekly guard growth.
- Mirror mandatory content bundle shape.
- Validate that branch-specific faction matching points to the correct spawn zone.

Use clear literal names in generated shared-center branches:

- `Spawn-1`, `Spawn-2`, `Spawn-3`
- `P1-N1`, `P1-N2`, `P1-N3`
- `P2-N1`, `P2-N2`, `P2-N3`
- `P3-N1`, `P3-N2`, `P3-N3`
- `Center`

Generated mandatory content names should line up with the branch names, for example:

- `mandatory_content_p1_n1`
- `mandatory_content_p2_n1`
- `mandatory_content_p3_n1`

## Implementation Notes

- Add a pure branch comparison helper that can compare normalized branch summaries.
- Keep branch summaries small: zones, connections, roads, guard settings, reward references, faction-matching references, and mandatory content references.
- Report the first mismatched player branch, field, and expected peer value.
- Avoid renaming imported user templates unless they are being regenerated by the app.

## Tests

Add focused Vitest coverage for:

- Valid mirrored 2-player branch layout.
- Valid mirrored 3-player branch layout.
- Missing cloned mandatory content in the third branch.
- `P3-N1` matching the wrong spawn faction.
- Mismatched N2/N3 guard values.
- Mismatched reward references.
- Stable generated names for branch zones and mandatory content.

## Acceptance Criteria

- Generated branches use clear literal names.
- Symmetric branch drift is detected before export.
- Faction matching mistakes point to the exact branch and spawn reference.
- `npm test` and `npm run build` pass.

## Non-goals

- Do not force asymmetric custom maps to become symmetric.
- Do not rename official reference templates.
